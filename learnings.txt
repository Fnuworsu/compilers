Parsing
   In parsing, tokens are transformed into an abstract syntax tree(AST).
   NB: AST represents the structure if a program. (AST will be root of the entire program)

   Features of the program
      - Contructs: if statements, while lopps, etc
      - Variables
      - constants
   
   Example:
      if (x < y) {
         z = 15;
         return z;
      } else {
         z = 5;
      }

      - Pseudocode for constructing the AST for this program
         // create if condition
         condition = BinaryOperation(op = ">", operandA = Var(x), operandB = Var(y))

         // create if body
         assign_if = Assigment(var = Var(z), rhs = Const(15))
         return = Return(al = Var(z))
         if_body = [assign_if, return]

         // create else body
         assign_else = Assigment(var = Var(Z), rhs = Const(5))
         else_body = [assign_else]

         // construct if statement
         if = If(condition = condition, body = if_body, else = else_body)

      - Nodes needed to support the above AST are programs, function declarations, statements, and expressions

         exp = Constant(int)
         statement = Return(exp)
         function_declaration = Function(string, statement)
         program = Program(function_declaration)

         - Right now, the program structure is very simple:
               - Program = one function: main
               - Function = a name and a body (just one statement for now)
               - Statement = only a return statement
               - Return = returns an expression
               - Expression = just an integer constant
         
         - As development continues:
               - Functions will have argument lists and return types
               - Statements will include conditionals and assignments
               - Expressions will support arithmetic
         
         - The AST (Abstract Syntax Tree) evolves over time to support these new features. For example, statement will later become:
               statement = Return(exp) | Assign(variable, exp)
      
      - Using Backus-Naur Form to properly define how series of tokens can be combined to form language constructs
               LHS            RHS
            <program> ::= <function>
            <function> ::= "int" <id> "(" ")" "{" <statement> "}"
            <statement> ::= "return" <exp> ";"
            <exp> ::= <int>
            
            LHS => non-terminal symbols
            RHS => terminal symbols

            - Using the production rule, we'll define how a language construct can built from other language constructs and tokens
            - Right now the grammar is extremely simple; there’s only one production rule for each non-terminal symbol 
                  - Add ons for later: non-terminal sybols having multiple production rules
                  Eg: <statement> ::= "return" <int> ";" | "int" <id> "=" <int> ";"
            
            - We use recursive descent parsing to transform a list of tokens into an AST
